# blends —— 设计体系糅合

> pattern 库沉淀的是**动效机制**(铁律 6:抄机制不抄样式)。
> 这一层沉淀的是被那条铁律扔掉的东西:**设计本体**——色板、字号阶梯、间距、运动节奏。
> 一个 blend = 取 N 个站的设计体系快照,按角色拆开重组成一个完整页面。

## 为什么要有这层

pattern 库能回答"我该用哪个效果",答不了"给我做个像 Igloo 那种气质的站"。
`criteria.md` 第 1 条复用性是一票否决,而整站气质恰恰最依赖原站语境——按现行口径它永远进不了 pattern 库,只能另开一层。

## 方法(两步)

**1. 取快照** —— 浏览器注入,遍历 `document.styleSheets` 统计声明频次 + 收集 `--*` 变量。产物写进 `cases/<站>/design-system.md`。

必须两路都取,只走一路会漏:

| 站的类型 | 设计体系在哪 | 只走另一路会得出 |
|---|---|---|
| 有 token 体系(Webflow / 设计系统站) | `--*` CSS 变量,一次全拿 | —— |
| 无 token 体系(手写 CSS) | 靠规则里的声明频次倒推 | "这站没有设计系统" |
| 动效在 CSS | `transition-duration` / `timing-function` 频次 | —— |
| 动效在 JS(GSAP 等) | **CSS 里取不到**,要读 JS 或实测 | "这站没动效" |

> 读样式表规则,不读渲染树:内嵌浏览器 pane 冻结时间轴时,滚动状态机驱动的站 DOM 里几乎没有文本(实测 Hashgraph innerText 仅 173 字符),遍历渲染树会一无所获。

**2. 定角色再糅合** —— 不是把两套 token 混在一起,是**按角色分配**:谁出骨架、谁出色板、谁出节奏。冲突处人来裁决,在注释里写清取舍理由。

## 口径:blend 不继承"零依赖单文件"铁律

那条铁律是给 **pattern demo** 定的——demo 的产物是可移植机制,带资产会妨碍移植。
**blend 的产物是一个页面,页面本来就该带字体和材质**。第一版守着铁律做,结果是纯色块 + 系统字,被判"简陋",而简陋的两个主因(字体、材质)恰恰都是铁律挡掉的。

blend 允许:外链/自带字体、图像、canvas 材质层。其余铁律(transform/opacity、reduced-motion、触屏键盘等价、强注意力效果一页一次、旋钮收口)照旧。

## pilot 结论(2026-07-26,第二版后修订)

**方法成立,值得留下,但不按"加进 case 模板 + 全量回填"的方式推广。**

### 第一版被判"简陋"暴露的事

取到的 token **是设计的语法,不是设计**。色板/字号/间距/缓动全部机械取到并正确落地,页面依然简陋,因为真正撑起气质的四样东西里有两样根本不在 CSS 里:

| 缺什么 | 性质 | 第二版怎么补的 |
|---|---|---|
| 定制字体(Brier / ParaboleWeb) | **快照取不到**,且商业授权 | 换免费近似字体顶位(Archivo 顶 Brier 的 heavy grotesque),中文 Noto Sans SC 900 |
| 摄影 / 3D 材质 | **快照取不到** | canvas 材质层 + 细网格罩,色斑只用原站色板 |
| 骨架(fixed 叠放叙事) | 快照取得到,第一版偷工只抄了 `//01` 编号 | 补上真骨架,四幕交叉淡入 |
| 文案 | 与设计无关,但占气质一半 | 重写成宣言体 |

**结论修正**:糅合的天花板是**资产**,不是方法。补上资产之后能到"像个正经站";补不上(字体买不起、没有摄影)就只能到"骨架不难看"。这也是当初 pivot 到 pattern 库是对的原因——动效机制是可搬运部分里唯一不依赖资产的一块。

成立的部分:

- 设计体系能被**机械取下来**,不靠印象。一次取样约 2 次注入,比写一篇 analysis 快得多
- 糅合结果是**可审计的**:每个 token 在 CSS 里标了 `[H]` / `[L]` 出处,能一眼看出哪来的、哪些被否决了
- 和 pattern 库是**咬合而非替代**:blend 出设计体系,pattern 出动效机制,两层拼起来才是完整页面

必须人来定的部分(不能自动化):

- **角色分配**:Lando 的荧光绿 + Hashgraph 的编号骨架能成立,反过来(Hashgraph 的冷蓝 + Lando 的赛道节奏)大概率不成立
- **冲突裁决**:本次否决了 Lando 的 16/48/100px 大圆角,采 Hashgraph 的近直角——理由是大圆角是消费品牌的"软",B 端要机构感
- **单位陷阱**:两站 rem 基准不同(Hashgraph 10px 流式根 vs Lando 16px 固定),数值直接混会全线错位 1.6 倍

为什么不全量回填 10 个老 case:

- 取样太快了,存起来的收益低于过期的风险。**Hashgraph 现在的首屏已经和 2026-07-15 写 analysis 时不一样了**(现在是发光晶体 + 水面)
- 快照是**带日期的证据,不是真相**。要糅合时现取,比翻半年前的快照可靠

一条贯穿的教训:**凡是靠 rAF 推进又"只播一次"的效果,都要问"rAF 不跑时停在哪一帧"**,停在错误状态的必须兜底。
